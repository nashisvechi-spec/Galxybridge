# Galaxy Bridge для Windows 10

Исходники самостоятельного приложения для общей мыши и клавиатуры между
ноутбуком и Android-телефоном. Целевая связка первой версии: **HP 240 G8,
Windows 10 x64 и Samsung Galaxy S25**.

Это аналог части возможностей Multi Control, а не клиент фирменной функции
Samsung. Есть отдельный режим Wi-Fi без отладки и прежнее подключение через ADB и управляющий канал scrcpy. Изображение
остаётся на экране телефона. Bluetooth для этой реализации не используется.

**Версия Windows 0.7.1 / Android LAN 0.7.2: тестовый режим Wi-Fi без отладки с отдельным
GalaxyBridgeLan.apk для Android 13+. QR внутри приложения телефона, сохранённое
сопряжение, поиск ноутбука после смены сети, файлы и базовое управление.
Добавлены скорость курсора 0,25–4× и отдельное окно для отправки файлов
перетаскиванием. Файлы с телефона отправляются через «Поделиться» или
«Отправить на ПК»; приёмная папка Windows выбирается в окне файлов.**

Начните с [инструкции Wi-Fi без отладки](docs/NATIVE_WIFI.ru.md).
Android 0.7.2 добавляет прямое нажатие на элемент под курсором через специальные
возможности, включая строки системного окна выбора файлов. Для этого служба
получает структуру активного окна; текст элементов не считывается кодом,
не сохраняется и не отправляется на ноутбук. Проверка на S25 ещё нужна.
Прежний режим ADB сохранён; описание его возможностей ниже.
Для автовозврата в режиме ADB по-прежнему используется Android-компонент 0.3.0.
Исходники проверены без сборки; новые функции на HP/S25 ещё не проверены.
Workflow запускается только вручную.

## Возможности первой версии

| Функция | Поведение |
| --- | --- |
| Подключение | USB или «Беспроводная отладка» Android; сопряжение кодом или QR |
| Автоподключение | При запуске ищет последний успешно подключённый телефон |
| Восстановление | Повторяет подключение после обрыва с паузой до 30 секунд |
| Мышь | Нативный курсор Android, три кнопки и вертикальная прокрутка |
| Клавиатура | Физические клавиши; русская и английская раскладки выбираются на телефоне |
| Переключение | Ctrl + Alt + F12 в обе стороны |
| Вход через край | Опционально: задержка у выбранного края экрана ноутбука 350 мс |
| Возврат | Автоматически через край телефона, обращённый к ноутбуку; Ctrl + Alt + F12 остаётся запасным способом |
| Буфер | Только текст; копирование на телефоне → Windows, Ctrl + V или Shift + Insert → телефон |
| Файлы | Перетаскивание в окно или выбор нескольких файлов; общая папка Download/GalaxyBridge |

В прежнем режиме ADB перетаскивание файлов между экранами, копирование картинок,
получение файлов с телефона, перенос курсора к границе при входе и медиа/Fn-клавиши
не поддерживаются. Для отправки с телефона используйте Wi-Fi без отладки 0.7.0.
В режиме ADB курсор телефона продолжает движение с его прежней
позиции. При входе с края ноутбука он не переносится автоматически к краю S25.

## Загрузить исходники в GitHub

1. Распакуйте исходный ZIP в отдельную папку.
2. Создайте пустой репозиторий в своём GitHub.
3. Загрузите **содержимое** папки в корень репозитория, включая `.github`.
   Файл `README.md` и папка `.github` должны лежать в корне, а не внутри
   дополнительной папки `GalaxyBridge`.
4. На этом можно остановиться: загрузка исходников не запускает сборку.

Надёжнее загрузить папку через GitHub Desktop либо Git, чтобы сохранить
папку `.github`. Вариант команд для Git из папки с исходниками:

```bash
git init
git add .
git commit -m "Initial Galaxy Bridge source"
git branch -M main
git remote add origin https://github.com/YOUR_NAME/YOUR_REPOSITORY.git
git push -u origin main
```

Замените `YOUR_NAME` и `YOUR_REPOSITORY` своим адресом. Авторизация проходит
обычным способом GitHub, токены не нужно вставлять в файлы проекта.

## Собрать позже через GitHub Actions

1. Откройте **Actions → Build Windows portable → Run workflow**.
2. Дождитесь завершения. В разделе **Artifacts** скачайте
   `GalaxyBridge-win10-x64`.
3. Распакуйте скачанный артефакт и вложенный ZIP приложения.
4. Запускайте `GalaxyBridge.exe` из полной распакованной папки.
   Рядом должна оставаться папка `backend`.

Workflow проверяет структуру проекта, запускает тесты протокола и HID,
собирает переносимое приложение x64, получает scrcpy 5.0.1 из официального
релиза и сверяет SHA-256 архива и сервера. Компонент автовозврата собирается
из Java-исходников с JDK 17 и Android SDK 35 в GalaxyBridgeEdge.apk.
APK находится рядом с EXE и в отдельном артефакте GalaxyBridgeEdge-android.
Для него используется тестовая подпись. .NET включается в сборку.
Workflow не создаёт GitHub Release и не подписывает EXE.

## Подготовить Galaxy S25

Начните с **USB**: так проще проверить разрешение отладки и работу ввода.

1. На S25: «Настройки → Сведения о телефоне → Сведения о ПО».
2. Несколько раз нажмите «Номер сборки», пока не включатся параметры
   разработчика. Подтвердите код блокировки, если телефон его запросит.
3. Откройте «Параметры разработчика» и включите «Отладка по USB».
   Названия пунктов могут отличаться между версиями One UI.
4. Подключите телефон кабелем для передачи данных, разблокируйте его
   и разрешите отладку для своего ноутбука в появившемся запросе.
5. Windows должен распознать ADB-устройство. Если оно не появляется,
   проверьте USB-драйвер, кабель и ограничения настроек телефона.
6. В Galaxy Bridge нажмите «Найти устройства», выберите готовый телефон
   со статусом `device` и нажмите «Подключить выбранный».

Root не нужен. Мышь и клавиатура работают через временный сервер ADB.
Для автоматического возврата требуется установить GalaxyBridgeEdge.apk.
Компонент основного управления временно запускается через разрешённую отладку. Она предоставляет ноутбуку
расширенный доступ к телефону: подтверждайте только свои компьютеры.
После использования можно отключить отладку и отозвать её разрешения.

Телефон должен быть разблокирован. Galaxy Bridge не обходит блокировку
экрана и не удерживает экран постоянно включённым.

## Один раз настроить автовозврат на S25

1. После ручной сборки найдите **GalaxyBridgeEdge.apk** рядом с EXE либо
   скачайте отдельный артефакт **GalaxyBridgeEdge-android**.
2. Подключите телефон в Windows-приложении. Основное управление работает
   и без APK. Во вкладке «Файлы» отправьте APK на телефон кнопкой «Выбрать файлы…».
3. На S25 откройте «Мои файлы → Внутренняя память → Download → GalaxyBridge», установите APK. Если Android
   запросит разрешение установки из этого источника, подтвердите его.
4. Откройте **Galaxy Bridge Edge** на телефоне и разрешите **показ поверх
   других приложений**. Разрешение на уведомления можно выдать отдельно.
5. Отключите и снова подключите телефон в Windows-приложении. Выберите
   расположение телефона и включите автовозврат. Журнал должен сообщить
   об APK 0.3.0, а после входа на телефон — о созданной зоне возврата.

APK не запрашивает доступ к Интернету, файлам, специальным возможностям,
захвату экрана или чтению уведомлений. Он получает события мыши только
в своей зоне и передаёт их по локальному каналу ADB. Служба работает
во время подключения к ноутбуку, без автозапуска при загрузке телефона.

**Тестовая подпись:** каждая сборка workflow создаёт новый ключ APK.
При обновлении на APK из другой сборки нужно удалить прежний
Galaxy Bridge Edge, установить новый и снова разрешить показ поверх
приложений. Для будущих обновлений без удаления понадобится постоянный
закрытый ключ подписи. Ключи не входят в артефакты.

## Подключить по Wi-Fi

1. Подключите телефон и ноутбук к одной доверенной сети без изоляции клиентов.
2. На S25 включите «Параметры разработчика → Беспроводная отладка».
3. Откройте «Сопряжение устройства с помощью кода».
4. В Galaxy Bridge нажмите «Сопряжение Wi-Fi». Введите **IP и порт из окна
   сопряжения**, затем шестизначный код.
5. Программа попробует найти порт подключения и открыть управление.
   Если это не удалось, вернитесь на основную страницу «Беспроводная отладка»,
   введите в приложении **IP и порт подключения с основной страницы**.
   Это другой порт. Нажмите «Подключиться по Wi-Fi».
6. Если управление всё ещё не открыто, нажмите «Найти устройства»,
   выберите нужный телефон и «Подключить выбранный».

Порт подключения может меняться. Если сеть или отладка перезапущены,
прочитайте актуальный адрес на телефоне. Для этой версии адрес вводится
вручную, если автоматическое обнаружение в сети не работает. Текущий порт
последнего телефона ищется через mDNS ADB. Код сопряжения не сохраняется и не передаётся в аргументах запуска процесса. Сам ADB
сохраняет ключ авторизованного компьютера стандартным способом.

## Сопряжение по QR-коду

В 0.5.1 сбой одного запроса mDNS больше не закрывает попытку сопряжения.
Если ADB не видит службу телефона, программа дополнительно отправляет
прямые mDNS-запросы через активные IPv4-интерфейсы Windows. Такой поиск
не требует перезапуска ADB или установки Bonjour. Он всё равно зависит
от разрешённого обмена в локальной сети и не обходит изоляцию клиентов.

1. Подключите S25 и ноутбук к одной Wi-Fi-сети; включите беспроводную отладку.
2. В Galaxy Bridge нажмите **«Сопряжение по QR-коду»**.
3. На S25 откройте **«Беспроводная отладка → Сопряжение устройства с помощью QR-кода»**
   и сканируйте код с экрана ноутбука.
4. Дождитесь подтверждения. Программа выполнит сопряжение и попробует
   найти отдельный порт подключения этого телефона, затем открыть управление.

Код действует две минуты. Для новой попытки нажмите «Новый QR-код». Используйте сканер в настройках беспроводной
отладки. QR генерируется локально, без обращения к сайтам. Его секрет
не записывается в настройки, журнал или аргументы запуска ADB.

Сканируйте встроенным сканером **беспроводной отладки**, а не обычной камерой.
Кнопка «Новый QR-код» отменяет прежнее ожидание и создаёт новое имя и секрет.
Журнал показывает этап: поиск, устройство обнаружено, сопряжение подтверждено
или время вышло. Секрет и полный QR-текст туда не записываются.
Для QR и поиска нового порта сеть должна пропускать mDNS. Если телефон
не обнаружен, проверьте разрешение ADB в брандмауэре Windows и изоляцию
клиентов на роутере. Остаётся сопряжение шестизначным кодом и ручной
IP:порт с основной страницы телефона. Повторное сопряжение не требуется
при каждом подключении, пока разрешение компьютера не отозвано на S25.

## Автоподключение и восстановление

На вкладке «Подключение» по умолчанию включены две отдельные настройки:

- **Автоподключение к последнему телефону при запуске** — работает после
  первого успешного подключения. Сначала проверяется уже доступный USB/Wi-Fi,
  затем найденный текущий Wi-Fi-порт и сохранённый адрес как запасной вариант.
- **Восстанавливать связь после обрыва** — освобождает управление ноутбуком
  и начинает поиск того же телефона. Повторы идут с паузами 2, 4, 8, 16,
  затем 30 секунд; длительность самой попытки добавляется к этой паузе.

Для обнаружения тихого обрыва Wi-Fi программа раз в три секунды выполняет
короткую проверку ответа телефона с таймаутом четыре секунды. После
восстановления нужно заново войти на телефон горячей клавишей или через край:
мышь и клавиатура сами на телефон не переключаются. При блокировке или сне
ноутбука автоматические попытки приостанавливаются до возвращения на рабочий
стол. Программа не включает отладку, Wi-Fi и не разблокирует телефон.

«Отключить», «Остановить автоподключение» и отмена фоновой попытки
приостанавливают повторное подключение до нового ручного подключения,
выключения/включения соответствующего флажка или перезапуска программы.
Кнопка **«Забыть последний телефон»** удаляет сохранённый профиль; она
не отзывает ключ ADB на телефоне.

Программа сохраняет в локальных настройках модель, серийный идентификатор,
GUID беспроводной отладки, последний транспорт и известный адрес подключения.
Пароли и коды сопряжения не сохраняются. Перед автоматическим запуском
управления идентификатор проверяется: другой телефон с прежним IP не будет
выбран. Если идентификатор недоступен, подключение возможно вручную, но
автоподключение для него не сохраняется.

## Управление и русский ввод

- Для входа на телефон нажмите **Ctrl + Alt + F12**. Если HP использует
  мультимедийный режим ряда F-клавиш, может потребоваться **Fn**.
- Для автоматического возврата на вкладке «Управление» выберите расположение
  телефона и включите «Автовозврат через край телефона» (по умолчанию включён).
  Двигайте курсор через край S25 в сторону ноутбука. Если телефон справа,
  возвращаться нужно через **левый край телефона**; если слева — через правый.
  При зажатых кнопках мыши или клавишах возврат не срабатывает. Курсор на ПК
  появляется у соответствующего края монитора с сохранением относительной
  позиции вдоль границы.
- Для возврата горячей клавишей нажмите то же сочетание. Его обработка
  остаётся на Windows и доступна независимо от автовозврата.
- Во время управления мышь и обычные клавиши направляются на телефон;
  курсор ноутбука скрыт. Перед переключением отпустите остальные клавиши
  и кнопки мыши.
- Для русского ввода после подключения откройте настройки физической
  клавиатуры на S25 и назначьте нужные раскладки для **Galaxy Bridge Keyboard**.
  Кнопка «Раскладка клавиатуры» отправляет запрос к настройкам Android.
  Приложение не переносит языковую раскладку из Windows автоматически.
- Если нужен вход через край, выберите сторону телефона и включите флажок.
  По умолчанию он выключен. Между настоящими мониторами Windows приложение
  курсор не перехватывает.
- «Общий текстовый буфер» можно отключить. При включении текст копирования
  на телефоне заменяет текстовый буфер ноутбука; вставка на телефон использует
  текущее содержимое Windows. Изображения и текст больше примерно 256 КБ
  не поддерживаются. Поведение сочетаний также зависит от приложения Android.
- Откройте вкладку «Файлы» и перетащите один или несколько файлов из
  Проводника в окно Galaxy Bridge. Или нажмите «Выбрать файлы…» и выделите
  несколько файлов с Ctrl/Shift. Телефон должен быть подключён.
- Файлы **копируются**, оригиналы остаются на ноутбуке. На телефоне откройте
  «Мои файлы → Внутренняя память → Download → GalaxyBridge».
  Все отправки сохраняются в этой общей папке. Учитываются уже лежащие
  в ней файлы и папки: одноимённые файлы получают суффиксы `(2)`, `(3)`.
  Старые подпапки из версии 0.5.0 остаются на месте; файлы из них не перемещаются.
- Индикатор показывает, что передача идёт, и номер текущего файла; процента
  передачи внутри одного файла нет. Для остановки нажмите «Отменить».
  Подтверждённые файлы сохраняются. Незавершённый файл имеет временное имя
  `.gb-….part`; программа пытается удалить его. При потере связи он может
  остаться в общей папке — его можно удалить вручную.
- При ошибке очередь останавливается. Восстановление связи не повторяет
  отправку автоматически: выберите оставшиеся файлы заново. Если обрыв
  произошёл при подтверждении переименования, проверьте папку на телефоне
  перед повтором: последний файл мог уже сохраниться.
- Папки и виртуальные вложения из почтовых программ не поддерживаются:
  сначала сохраните их как обычные файлы. Имена ограничены 255 байтами UTF-8.
  Передача работает через USB и Wi-Fi и не требует новой версии APK.
  Для одного файла предусмотрено до 30 минут и возможность отмены.
- Если перетаскивание из Проводника не срабатывает, запустите Galaxy Bridge
  обычным способом без прав администратора или используйте выбор файлов.

Сворачивание прячет окно в область уведомлений. Открыть его можно двойным
щелчком по значку. «Выход» закрывает связь и освобождает перехват ввода.
При разрыве связи, блокировке Windows или переходе в сон управление
возвращается ноутбуку. Эти сценарии требуют проверки на реальном устройстве.
Ctrl + Alt + Delete остаётся системным сочетанием Windows.

Для автовозврата используется прозрачная полоса шириной **4 физических
пикселя** у края доступной области телефона, с учётом системных панелей
и выреза экрана. Она существует только во время управления и может
перехватить касание в этой полосе. При возврате, отключении или остановке
компонента полоса удаляется. После потери канала она удаляется по таймауту
чтения 6 секунд. Некоторые приложения могут скрывать сторонние окна;
в таком случае используйте Ctrl + Alt + F12. Работа зоны на One UI
требует проверки на реальном S25.

## Если не работает

| Симптом | Что проверить |
| --- | --- |
| Нет `backend` | Используйте полный артефакт сборки или выполните Fetch-Backend.ps1 |
| `unauthorized` | Разблокируйте S25 и подтвердите запрос отладки |
| `offline` | Переподключите кабель или адрес беспроводной отладки |
| Wi-Fi не соединяется | Проверьте отдельные порты сопряжения и подключения, сеть и брандмауэр |
| QR не находит телефон | Откройте сканер QR в беспроводной отладке; проверьте mDNS, общую сеть и изоляцию клиентов; используйте сопряжение кодом |
| Автоподключение не начинается | Нужно хотя бы одно успешное подключение, сохранённый профиль и соответствующий флажок; после ручной остановки включите его заново |
| Разрешение ADB отозвано | Разрешите свой ноутбук или выполните сопряжение заново; программа не подтверждает запрос за вас |
| Нет мыши/клавиатуры | Посмотрите журнал; доступ UHID и запуск сервера нужно проверить на One UI |
| Неверные буквы | Выберите раскладки именно физической клавиатуры на телефоне |
| Горячая клавиша не срабатывает | Проверьте Fn/F12 и конфликт с другим приложением |
| Курсор не возвращается через край | Используйте Windows-версию 0.5.1 и APK 0.3.0; проверьте разрешение поверх приложений, сторону телефона и журнал; отпустите кнопки и клавиши |
| В журнале нет компонента автовозврата или ошибка Android | Установите APK, откройте его, разрешите показ поверх приложений и переподключитесь; сохраните текст ошибки из журнала |

Ошибка **Unknown pid=… uid=2000** в версии 0.2.x означает, что оконная
система не нашла процесс ADB в списке процессов обычных приложений.
Подготовка контекста в версии 0.2.1 этого не устраняет. Начиная с версии 0.3.0 программа создаёт
окно в процессе установленного APK, зарегистрированном Android.
Обновите Windows-папку целиком и установите APK. Если ошибка останется,
скопируйте текст вкладки «Помощь и журнал». Успешное создание окна отмечается
сообщением «Зона автовозврата создана на телефоне».

Программа не устанавливает драйверы, не меняет модель ноутбука в реестре
и не разблокирует Samsung Multi Control. Замена Bluetooth-адаптера для неё
не требуется. Производительность Wi-Fi и драйвер ADB проверяются отдельно.

## Локальная сборка для разработчика

Требуется Windows x64, .NET SDK 8 с поддержкой C# 12, JDK 17 и Android SDK
с пакетами `platforms;android-35` и `build-tools;35.0.0`. Укажите `JAVA_HOME`
и `ANDROID_HOME`. Команды PowerShell
ниже **создают приложение**; выполнять их стоит, когда сборка понадобится.

```powershell
python scripts/check_sources.py
dotnet run --project tests/GalaxyBridge.Core.Tests/GalaxyBridge.Core.Tests.csproj -c Release
dotnet publish src/GalaxyBridge.Windows/GalaxyBridge.Windows.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o artifacts/GalaxyBridge
./scripts/Fetch-Backend.ps1 -Destination artifacts/GalaxyBridge/backend
./scripts/Build-EdgeHelper.ps1 -Destination artifacts/GalaxyBridge
Copy-Item README.ru.md, LICENSE, THIRD_PARTY_NOTICES.md -Destination artifacts/GalaxyBridge
Copy-Item licenses -Destination artifacts/GalaxyBridge -Recurse
```

Для запуска из IDE предварительно получите backend в выходную папку IDE.
Скрипт загрузки получает официальные исполняемые компоненты, но не собирает
исходники приложения. Бинарники backend не следует коммитить в репозиторий.
