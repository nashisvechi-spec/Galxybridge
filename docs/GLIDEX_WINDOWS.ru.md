# GlideX Windows: путь системной мыши

## Результат

Предоставленная Windows-версия GlideX содержит собственный драйвер
`GlideXInputDevice.sys` для **Classic Bluetooth HID**. Это другой транспорт,
чем BLE HID / HOGP, реализованный сейчас в Galaxy Bridge. Отрицательное значение
`BluetoothAdapter.IsPeripheralRoleSupported` проверяет возможность нашей BLE-
периферии; оно не устанавливает совместимость адаптера с Classic Bluetooth HID.

Пользователь подтвердил работу GlideX на своём ноутбуке с Realtek Bluetooth 4.2
и Galaxy S25. Это свидетельство работы GlideX на этой конфигурации, но не
натурная проверка будущего драйвера Galaxy Bridge. Переключатель overlay не
добавляет отсутствующий Bluetooth-транспорт: он нужен для границ мыши и буфера.

## Подтверждённая цепочка

| Компонент | Что обнаружено | Значение |
|---|---|---|
| `ModuleDll/GlideXModule/GlideXMirror.exe` | `CreateFile`, `DeviceIoControl`, диагностика `IOCTL_ASUS_HID_CONNECT`, `IOCTL_ASUS_HID_DISCONNECT`, `IOCTL_HID_MOUSE_EVENT`, `SendHIDRequest` | Windows-модуль обращается к драйверу для подключения и передачи ввода |
| `ModuleDll/ServicePackage/GlideXServiceInstaller.exe` | Inno Setup с MSI x64 и ARM64; версия сервисного пакета 4.3.4.0 | Драйвер поставляется вместе с сервисным установщиком |
| MSI x64 | `GlideXInputDevice.inf`, `GlideXInputDevice.sys`, каталог подписи и `GlideXService.exe` | Для системной мыши существует отдельный пакет драйвера |
| INF x64 | Класс Bluetooth, kernel service `GlideXInputDevice`, версия 1.0.3.0 от 29.05.2023, привязка к `BTHENUM` и служебному UUID | Драйвер работает через стек Bluetooth Windows |
| Драйвер x64 | Каналы PSM `0x11` / `0x13`, SDP service class `0x1124` | Стандартные HID Control / HID Interrupt и HID service class классического Bluetooth |

`GlideXMirror.exe` также содержит обработку относительной мыши, колеса,
модификаторов и шести клавиш, а также отдельную абсолютную калибровку.
Наличие этих обработчиков не означает, что все отчёты и размеры буферов драйвера
полностью восстановлены. Числа в дизассемблере сопоставлены со стандартом HID,
а не с описанием BLE GATT.

## Самостоятельный режим Galaxy Bridge

Для сходной совместимости нужен собственный **Bluetooth profile driver Windows**,
который публикует HID SDP и обслуживает L2CAP Control / Interrupt. Обычный RFCOMM-
сокет или изменение проверки BLE Peripheral не создают HID-мышь на Android.
Microsoft документирует доступ к L2CAP через kernel-mode DDI стека Bluetooth.

Предлагаемая независимая архитектура:

1. Собственный пакет драйвера и установщик Windows с обычным запросом прав
   администратора при установке. Использовать собственные идентификаторы,
   службу и UUID; конкретную привязку к радио/служебному устройству проверить
   при разработке профиля.
2. Системное сопряжение с телефоном через настройки Windows. Android-приложение
   запрашивает обычные разрешения Bluetooth; дополнительные служебные каналы,
   если потребуются для обнаружения профиля, проектируются отдельно от HID.
3. Подключение только к явно выбранному доверенному телефону. Состояние «готово»
   определяется работой обоих HID-каналов, а не наличием записи сопряжения.
4. Отдельный транспорт `IPhoneControl`, использующий имеющуюся очередь
   `HidReportPump`, управление кнопками, модификаторами и отпускание при выходе.
   Формат Classic HID пакета согласовать с опубликованным дескриптором;
   BLE-отчёты нельзя переслать без этой обработки.
5. Файлы, текстовый буфер и обратная связь от края остаются в авторизованной
   LAN-сессии. Wi-Fi сенсорное управление остаётся доступным при отсутствии
   готовой HID-связи.

Для обычной установки на современных Windows драйвер должен пройти применимый
процесс подписи Microsoft. Подпись EXE или APK не заменяет подпись kernel-драйвера.
Процесс требует учётной записи Hardware Dev Center и соответствующего
сертификата; затем нужны сборка WDK и проверки на настоящих Windows/телефоне.
Отладка Android для такого пути не нужна.

Драйвер ASUS и его DLL не включены в Galaxy Bridge. Найденные лицензии сторонних
компонентов установщика не устанавливают лицензию на самостоятельное
распространение `GlideXInputDevice.sys`. Зависимость от установленного GlideX
также не даёт самостоятельного режима Galaxy Bridge.

## Что изменено и что ещё не выполнено

Windows 0.7.8 исправляет диагностику: отсутствие BLE Peripheral больше не
выдаётся за общую несовместимость Bluetooth-адаптера. Существующий BLE HID
и Wi-Fi продолжают работать по прежней схеме. Android остаётся версии 0.7.8.

**Собственный Classic Bluetooth HID-драйвер и транспорт пока не реализованы.**
Эта редакция не включает системную мышь на адаптере, где текущий BLE-режим
недоступен. Сборка приложения не решает задачу подписи и проверки нового драйвера.
