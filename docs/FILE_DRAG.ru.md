# Перетаскивание файлов · Windows 0.7.13 / Android 0.7.15

Первый тестовый вариант: из карточки Galaxy Bridge на телефоне в рабочий стол
или папку Проводника. Управление мышью — **по Wi-Fi**. Bluetooth-мышь и
перетаскивание непосредственно из «Моих файлов» / «Галереи» пока не поддерживаются.

1. Обновите обе программы до 0.7.13. Для Android используйте APK с прежней
   подписью из существующего ручного workflow — обновление поверх установленного.
2. На ПК откройте окно файлов и включите «Принимать файлы с сопряжённого телефона».
3. На телефоне откройте «Отправить на ПК», выберите файлы и нажмите
   «Подготовить для перетаскивания на ПК». Дождитесь сообщения «Готово».
4. Включите управление телефоном мышью по Wi-Fi. Если тестовый Bluetooth-режим
   подключён, отключите его в Galaxy Bridge на ПК.
5. Зажмите синюю карточку левой кнопкой мыши. Потяните её к краю телефона со
   стороны ПК, удерживая кнопку. Если телефон настроен справа — тяните влево;
   слева — вправо; сверху — вниз; снизу — вверх.
6. Курсор вернётся на ПК с файлами. Наведите его на рабочий стол или нужную
   папку Проводника и отпустите кнопку. **Esc** отменяет перетаскивание.

Это копирование: оригиналы на телефоне сохраняются. При подготовке подборка
передаётся по существующему TLS-соединению, с проверкой размера и SHA-256.
В пользовательскую папку приёма она не записывается. Подборка ограничена
100 файлами и 2 ГБ суммарно. При повторном перетаскивании подготовьте её заново.

Windows получает обычный `FileDrop` через OLE и выбирает конечную папку.
Перетаскивание разрешено только при активном захвате Wi-Fi, зажатой левой
кнопке, движении наружу и совпадении поколения захвата. При отпускании кнопки
до возврата, блокировке ПК, разрыве соединения или отключении приёма операция
отменяется. Приложение не имитирует нажатие мыши на рабочем столе.

После успешной передачи в Windows временные исходники оставляются для
асинхронного копирования Проводником. Кэши старше 24 часов очищаются при
следующем запуске. При отмене, замене неподтверждённой подборки или разрыве
связи незадействованные подготовленные файлы удаляются сразу. Отмена на ПК
не удаляет исходники телефона и уже полученные обычным способом файлы.

## Проверка на устройствах

- Один маленький TXT, фото, PDF; затем несколько файлов и два одинаковых имени.
- Все четыре расположения телефона; рабочий стол, открытая папка и подкаталог.
- Отпустить кнопку до края: курсор остаётся на телефоне, файл не копируется.
- Esc после перехода: файл не появляется в целевой папке.
- Отключить сеть, выключить приём, заблокировать ПК во время перетаскивания.
- Большой файл: подготовка отдельно, плавность обычной мыши без изменений.
- Обновить APK поверх 0.7.11, проверить прежнюю подпись и сохранение сопряжения.

Компиляция и тесты протокола не заменяют эту проверку Windows/S25.

## Приём из «Моих файлов» · Android 0.7.14

Добавлен проверочный приёмник стандартного Android drag-and-drop. Это пока
два жеста: из файлового менеджера в приёмник, затем из подготовленной карточки
на ПК. Самостоятельное вытягивание файла из «Моих файлов» через край телефона
ещё не реализовано. Работа исходного перетаскивания из карточки в Windows
подтверждена пользователем; приём из Samsung нужно проверить на устройстве.

1. Запустите существующий ручной **Build Windows portable** и обновите APK
   поверх установленного. В заголовке Android будет **0.7.15**. ПК достаточно
   оставить на **0.7.13**; новый APK использует прежний протокол.
2. В Galaxy Bridge нажмите **Приём из «Моих файлов»**. Через «Недавние» и меню
   значка приложения откройте приёмник и «Мои файлы» рядом: разделение экрана
   или всплывающее окно. Синяя область приёма должна быть видна.
3. Для первой проверки используйте палец: зажмите маленький TXT, JPG или PDF
   в файловом менеджере, дождитесь начала перетаскивания, перенесите его в
   синюю область и отпустите. Затем повторите мышью по Wi-Fi. Неподвижное
   удержание мыши может потребовать примерно два интервала долгого нажатия.
4. Ожидаемый результат: **Доступ к чтению подтверждён: 1**, имя и размер.
   Это проверка открытия и первого байта, а не проверка всего содержимого.
   Пустой файл также допустим. Неизвестный размер показывается явно.
   Сеть и сопряжение для этой проверки не нужны; файл ещё не отправляется.
5. Подключите ноутбук, включите приём файлов на Windows. Нажмите
   **Подготовить для переноса на ПК**. Откроется прежнее окно отправки и
   начнётся подготовка. Дождитесь «Готово» и перетащите синюю карточку
   мышью по Wi-Fi в нужную папку Windows, как в инструкции выше.

Если отображается только «Ожидаем перетаскивание», источник мог не запустить
межприложный drag-and-drop. Если перетаскивание обнаружено, но сброс не принят,
приёмник покажет причину: текст вместо файла, неподдерживаемая ссылка, отсутствие
разрешения или невозможность прочитать содержимое. Используйте существующее
**Поделиться → Galaxy Bridge Wi-Fi**. По выделению строки или её имени нельзя
считать доступ к файлу подтверждённым.

Ограничения: от 1 до 100 файлов, повторные URI учитываются один раз. Известные
размеры проверяются на суммарный лимит 2 ГБ; при неизвестном размере окончательный
лимит проверяет существующая подготовка на ПК. Проверка идёт в отдельном потоке,
её можно отменить; через 20 секунд запрашивается отмена зависшего провайдера.
Провайдер может не ответить на отмену сразу — новый сброс доступен после завершения
предыдущей проверки. Сброс во время отправки отклоняется.

Права на чтение временные: окно приёмника удерживает `DragAndDropPermissions`,
передаёт `ClipData` и read-grant в окно отправки перед закрытием. Не закрывайте
окно отправки во время подготовки. После пересоздания приёмника сброс нужно
повторить; сохранённая ссылка не выдаётся за действующее разрешение. Доступ ко
всему хранилищу не запрашивается, оригиналы не изменяются и не удаляются.

Дополнительная проверка на устройстве: несколько файлов, пустой TXT, большой
файл, отмена проверки, текст вместо файла, повторный сброс, смена ориентации
и закрытие окна. Отдельно проверить завершение подготовки после закрытия
приёмника: это проверяет передачу временного разрешения в окно отправки.

### Разбор данных и диагностика · Android 0.7.15

На записи проверки 0.7.14 область реагирует на drag и сброс, но выдаёт
«Получено название, текст или неподдерживаемая ссылка…». Эта ошибка возникала
до запроса разрешения и чтения: прямое поле `ClipData.Item.getUri()` было пустым
либо содержало схему, отличную от `content`. По видео нельзя различить эти
варианты и узнать содержимое пакета сброса.

0.7.15 дополнительно проверяет ссылки в `Item.getIntent()`: `Intent.data`,
вложенный `ClipData`, стандартный `EXTRA_STREAM` (одна ссылка или подборка)
и стандартный `EXTRA_INTENT`. Поддерживается также целая `content://`-ссылка
в текстовом поле. Прямая ссылка имеет приоритет над её альтернативным текстовым
представлением; в Intent приоритет имеют файлы из ClipData / EXTRA_STREAM.
Обычное название, путь `/storage/...`, `file://`, веб-адрес или сериализованный
`intent://` не превращаются в доступ к файлу. Полученный Intent не запускается.

Теперь отсутствие отдельного объекта drag-разрешения не считается автоматическим
отказом: проверяется фактическое чтение, которое может быть разрешено ранее или
самим провайдером. При запрете чтения приёмник покажет ошибку, файлы не отправляются.

При следующем тесте повторите сброс того же небольшого файла. Если чтение не
подтверждено, нажмите **Скопировать диагностику сброса** и пришлите текст.
Она показывает MIME, наличие URI/Intent/текста, схемы ссылок, названия и типы
полей extras; значения extras, содержимое файлов и полные ссылки не выводятся.
Это поможет определить специфический формат исходного менеджера, если он не
использует поддерживаемые стандартные поля. Широких прав на хранилище нет.
