# Системная мышь: исследование и реализация Windows 0.7.4

Задача — передавать обычные события мыши и позволить Android обрабатывать их
так же, как ввод подключённой физической мыши. Нельзя обещать одинаковое меню
во всех приложениях: результат правого, среднего, двойного клика и выделения
определяют Android и конкретное приложение.

## Что установлено

`AccessibilityService.dispatchGesture` создаёт сенсорный ввод. AOSP
`MotionEventInjector` использует `SOURCE_TOUCHSCREEN`, нулевые `buttonState` и
`metaState`. Продолженные жесты исправляют перетаскивание в реальном времени,
но не превращают эти события в `SOURCE_MOUSE` и не создают системный курсор.
Разрешение overlay этого не меняет.

Обычный APK не получает `INJECT_EVENTS`: в манифесте AOSP это разрешение
уровня `signature`. `BluetoothHidDevice` на Android имеет обратное направление:
телефон становится периферией, поэтому он не решает задачу управления телефоном
с Windows. `VirtualDeviceManager` также не является общедоступной заменой:
виртуальные устройства имеют ограничения, а ComputerControl требует системной
поддержки, роли ассистента, allowlist и согласия для отдельных приложений.

Подход без отладки — Windows как BLE HID-периферия (HOGP). Microsoft предоставляет
пример `VirtualKeyboard` на `GattServiceProvider`; API позволяет публиковать HID
и адресовать уведомление конкретному подписавшемуся клиенту. Обязательное условие
на ноутбуке — `BluetoothAdapter.IsPeripheralRoleSupported`. Совместимость адаптера,
Windows и HID-профиля конкретного телефона устанавливается натурной проверкой,
а не наличием обычного Bluetooth-сопряжения.

Другие подтверждённые варианты — уже используемый UHID через ADB (USB или Wi-Fi)
и AOA HID через USB без отладки. AOA исследован, но в эту реализацию не добавлен.

## Что реализовано

| Действие | BLE HID / ADB UHID | Сенсорный LAN |
|---|---|---|
| Системный курсор и его форма | Управляет Android | Стрелка приложения |
| Наведение без нажатия | Обычное движение мыши | Только движение стрелки |
| Пять кнопок, включая боковые | Передаются DOWN и UP всех пяти | Три кнопки: касание, Назад, Недавние |
| Двойной/тройной клик | Последовательность физических нажатий; распознаёт приложение | Сенсорные касания / доступное действие элемента |
| Удержание и перетаскивание | Движение с сохранёнными кнопками | Продолженные сенсорные жесты |
| Выделение текста, Shift/Ctrl + мышь | Реальные HID-клавиши и кнопки, одна упорядоченная очередь | Сенсорное выделение с долгим нажатием и маркерами |
| Вертикальное и горизонтальное колесо | Wheel и Consumer AC Pan | Вертикальный свайп |
| Возврат на ПК | Ctrl+Alt+F12; край телефона также поддержан в ADB с Edge APK | Горячая клавиша и край телефона |

`Hid.MouseDescriptor` и `MouseReports` описывают пять кнопок, относительные X/Y,
вертикальное колесо и AC Pan. Суммарное движение сохраняется при разбиении на
8-битные отчёты. Windows-хук обрабатывает `WM_XBUTTONDOWN/UP` и `WM_MOUSEHWHEEL`,
сохраняет отдельные остатки для обеих осей колеса и отправляет движение перед
изменением состояния кнопки. Для начала захвата нужно отпустить все пять кнопок.

`BleHidSession` публикует стандартные HID Information, Report Map, два Input
Report с Report Reference, LED Output Report, HID Control Point и Battery Service.
Передача идёт по зашифрованному соединению и только выбранному телефону,
подписанному на оба входных отчёта. Другие подключённые устройства не получают ввод.
Boot Protocol не объявляется; используется Report Protocol. Чтение состояния
мыши не повторяет относительное движение и колесо.

`HidReportPump` сериализует клавиатуру и мышь. Возврат управления отменяет
накопленный ввод, затем отправляет нейтральные отчёты старому адресату. Переполнение
очереди и отказ транспорта останавливают захват, а не теряют отпускание кнопки.
Завершение ожиданий ограничено по времени.

В Bluetooth-режиме LAN остаётся транспортом файлов и общего буфера. При входе
не запускается сенсорный курсор/overlay; при возврате после отпускания HID-клавиш
запрашивается текст телефона через существующий защищённый LAN-протокол.
Ctrl+V остаётся обычным сочетанием физической клавиатуры. Её раскладка задаётся
на Android. Для общего буфера по-прежнему нужно разрешение overlay на телефоне.

## Как включить

1. Собрать Windows 0.7.4 ручным Actions workflow и открыть окно Wi-Fi без отладки.
2. Нажать **Системная мышь по Bluetooth (тест)**. Приложение проверит адаптер.
3. В Bluetooth телефона найти ноутбук и подтвердить сопряжение на обоих устройствах.
4. Выбрать именно этот телефон в окне Windows и нажать **Управлять телефоном**.
5. Возвращаться на ПК через Ctrl+Alt+F12. Для файлов и буфера подключить тот же
   телефон обычным LAN QR. Android LAN 0.7.7 подходит; новый APK для BLE не требуется.

Для мыши не нужны отладка, root и специальные возможности. BLE-сопряжение является
отдельным системным подтверждением, его обычный LAN QR пока не заменяет.
Автоматическое восстановление HID-подписок после перезапуска Windows-приложения
не гарантировано: при необходимости нажать **Подключить** в Bluetooth телефона.
Если подписки не появились, заново выполнить Bluetooth-сопряжение. Состояние
**готово** показывается по двум HID-подпискам, а не только по факту парного устройства.

При неподходящем адаптере доступна кнопка **Системная мышь по Wi-Fi + QR**:
она закрывает LAN-окно и открывает существующее QR-сопряжение ADB. Для него
нужно включить беспроводную отладку и пользоваться её QR-сканером на телефоне.

Передача файла между устройствами не становится Android drag-and-drop от
наличия HID-мыши; для неё остаётся отдельное окно файлов и «Поделиться».
Кнопки изменения DPI и фирменные макросы мыши находятся вне пяти стандартных кнопок.

## Проверка и источники

Исходники Windows/Core скомпилированы с .NET 8, Windows SDK 19041 и предупреждениями
как ошибками. Прошли 2284 Core-проверки. Отдельные тесты проверяют независимый разбор размеров HID-дескриптора,
кнопки/обе оси колеса, порядок модификаторов и мыши, адресата, отмену накопленного
ввода, переполнение/отказ транспорта и сохранение LAN-буфера без сенсорного capture.
Проверка реального WinRT GATT, Bluetooth-сопряжения, выделения в приложениях,
подписей и восстановления на HP/S25 здесь не выполнена. EXE/APK не упакованы;
полный MSBuild в этой среде завершается внутренней ошибкой Process.GetProcessName.
