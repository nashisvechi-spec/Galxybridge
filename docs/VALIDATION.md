# Статус проверки исходников

Дата подготовки: 9 октября 2026. Версия Windows: **0.6.2**, Edge-компонент: **0.3.0**, LAN-компонент: **0.6.1**.

На S25 версия 0.2.1 сообщила WINDOW_ADD_IllegalStateException:
Unknown pid=4590 uid=2000. В коде Android Session.java такой текст появляется
при отсутствии вызывающего процесса в карте процессов ActivityTaskManager.
Исправление локального контекста в 0.2.1 не устраняет эту причину.
В 0.3.0 окно перенесено в процесс установленного APK, запускаемый обычной
службой Android. Пользователь подтвердил работу автовозврата на своей связке HP/S25 9 октября 2026.
Это подтверждение относится к установленной у него версии, а не к новой отправке файлов.

В Windows 0.4.0 добавлены расписание повторов, проверка ответа телефона,
идентификация сохранённого устройства и QR-сопряжение по протоколу ADB.
Зависимости QRCoder 1.8.0 и System.Drawing.Common 8.0.30 закреплены в проекте;
API QR и лицензия проверены
по исходникам этого тега. Пакет не скачивался и не выполнялся локально.

Проверка исходников использует Python и не запускает сборку. Она не заменяет
компилятор. .NET SDK, JDK и Android SDK в текущей среде отсутствуют.

Переносимые C# тесты проверяют протокол, HID, Unicode, rollover, сетевые
адреса, ADB-состояния и фрагментированный поток. Для автовозврата добавлены
проверки эпохи, свежести события, направления, удержания клавиш/кнопок,
координат мониторов и фактической зоны с отступами системных панелей.
Новые случаи отклоняют пустую, толстую, отрицательную, выходящую за экран
и переполняющую целые числа зону. Эти тесты выполняются только в ручном
workflow; при подготовке изменений они не запускались.

EXE, APK и workflow при подготовке не собирались и не запускались согласно
запросу пользователя. Используйте [TESTING.md](TESTING.md) после ручной сборки.

В Windows 0.5.0 добавлены вкладка «Файлы», перетаскивание в окно, выбор
нескольких файлов, отдельные папки отправок, суффиксы одноимённых файлов,
временные .part-файлы и отмена. Добавлены C# проверки безопасных имён,
UTF-8 ограничения, дубликатов и экранирования shell. Они не запускались
локально: .NET SDK отсутствует. Структурная проверка исходников не заменяет
компиляцию, проверку WinForms/OLE и реальную передачу через ADB.
Android-компонент, его разрешения и workflow не изменены.

Локально также проверены команды подготовки/переименования/очистки на POSIX
shell и экранирование шести имён с кириллицей, emoji, пробелом, апострофом,
метасимволами $(), ; и обратными кавычками. Константа экранирования взята
из C# исходника. Проверена сохранность существующего файла при конфликте.
Это проверка команд на локальной системе, не выполнение C# и не тест Android.

Пользователь сообщил, что QR-сопряжение не работает; этап/сообщение ошибки
пока не предоставлены, поэтому исходная причина на HP/S25 не установлена.
В 0.5.1 исправлено завершение ожидания при единичном сбое, добавлены повторные
попытки, кнопка нового кода, нормализация имён служб и прямой IPv4 mDNS-поиск
соединения/сопряжения. Передача файлов перенесена в общую папку с учётом
существующих имён. Добавлены C# проверки DNS wire, сжатия, границ/мусорных
пакетов и конфликтов имён. Они не выполнялись локально.
Ни исправление QR на телефоне, ни UDP/OLE на Windows не проверялись.
Компиляция и сборки не запускались; Android-компонент и workflow сохранены.

Для 0.5.1 локально проверены обновлённые команды общей папки: NUL-список
первого уровня, имена с метасимволами/Unicode/переводом строки, отказ от
замены файла, каталога и висячей ссылки, очистка только временного файла.
Это запуск команд на локальном POSIX shell, а не на Android. DNS/UDP
и C# тесты не запускались; структурная проверка включает новые файлы.

## 0.6.0: независимый LAN-режим

Добавлены отдельный Android пакет/сканер QR, TLS с проверкой отпечатка сертификата,
DPAPI-хранилище доверия Windows, постоянный токен, Wi-Fi broadcast discovery,
повторы подключения и самостоятельный input engine через AccessibilityService.
Файлы идут блоками в app-owned pending MediaStore Download/GalaxyBridge с SHA-256.

Проверка синтаксическими деревьями tree-sitter: 26 C# и 11 Java файлов без ошибок
разбора. Проверка XML/структуры/ручного workflow выполнена scripts/check_sources.py.
На JVM выполнены **42 assertions реальных Wire.java / Pairing.java**, используя
эталонный org.json 20240303 только для теста. В production используется Android
org.json; JVM-тест не проверяет Android framework. Тесты компилировались отдельно,
приложение/EXE/APK не собирались. Проверен SHA-256 скачанного ZXing 3.5.3 JAR
с контролем опубликованной SHA-1 суммы Maven; hash закреплён в скрипте сборки.

Новые C# assertions написаны, но .NET SDK отсутствует: компиляция C# и тесты C#
не выполнялись. JDK javac API доступен через java, Android SDK отсутствует.
Build-LanCompanion.ps1, D8/aapt2, подпись APK и управление на S25 не запускались.
Workflow не dispatch-ился. Native Wi-Fi — предварительная реализация для проверки
на устройстве, не подтверждённый готовый релиз. Старое подтверждение работы
автовозврата относится только к прежнему ADB-режиму.

## Исправление сбоя workflow 0.6.0

В запуске https://github.com/nashisvechi-spec/Galxybridge/actions/runs/37980143475
этап Run portable protocol tests остановился с CS0136: переменные `length`
и `invalid` новых LAN-тестов пересеклись с именами в общей области top-level
Program.cs. Они переименованы в `lanFrameLength` и `lanFrameRejected`; сами
проверки сохранены. Версия приложения не меняется, поведение не изменено.

После исправления загружен SDK .NET 8.0.425. Обычные dotnet/MSBuild команды
в этой среде останавливаются на доступе к сведениям о процессе, поэтому
проверка выполнена прямым запуском Roslyn 4.11.0 с reference assemblies .NET 8:
ядро и тестовый runner скомпилированы, **2164 core assertions прошли**.
Весь C# код Windows дополнительно проверен компилятором как временная библиотека
с WindowsForms reference profile, QRCoder 1.8.0 и ProtectedData 8.0.0.
Предупреждения несовпадения версий ссылок CS1701/CS1702 подавлены, как в SDK;
остальные предупреждения компилятора считались ошибками. Это проверка типов и
C# кода, не запуск WinForms и не полноценный SDK publish с анализаторами.

EXE/APK не созданы, workflow автоматически не перезапускался. Для проверки
полной цепочки нужен новый ручной запуск workflow на main с исправленным
коммитом. Старый failed run по-прежнему относится к прежнему коммиту.

## 0.6.1: TLS и диагностика QR-сопряжения

Пользователь сообщил: после сканирования сопряжение не произошло. Точный этап
на устройстве неизвестен. В коде Windows выявлен EphemeralKeySet, несовместимый
с Schannel в ряде конфигураций: Microsoft описывает ошибку 0x8009030E в
https://learn.microsoft.com/en-us/dotnet/core/extensions/sslstream-troubleshooting.
Импорт переведён на UserKeySet без PersistKeySet, с сохранением прежнего PFX,
отпечатка и DPAPI-профиля. Сертификат остаётся живым до закрытия всех сессий.
Для телефона, который использует TLS 1.2, сервер также выбирает TLS 1.2.

Строка сетевой диагностики теперь отдельная и не стирается таймером UI:
поступление TCP, TLS, проверка запроса, сохранение токена и подтверждение.
Ошибки содержат только локальный этап, имя класса исключения и код; секреты
и содержимое пакетов не выводятся. Отклонённый/истёкший QR объясняется отдельно.

Добавлен самостоятельный тестовый проект, который использует настоящий
LanIdentity.cs и временную папку вместо данных пользователя. На Linux выполнены
8 TLS assertions: импорт, повторный импорт, неизменность отпечатка, обмен
данными по TLS 1.2 и отказ с неверным отпечатком. Они используют OpenSSL,
не Schannel. Windows workflow дополнительно проверяет создание и повторную
загрузку DPAPI-профиля и TLS с обоими сертификатами (16 assertions всего);
этот Windows-тест здесь не выполнялся. Проект и весь код Windows проверены
прямым компилятором C#; структурная проверка исходников прошла.

Android-код и формат протокола не менялись. Уже установленный APK 0.6.0
подходит. EXE/APK не собирались, workflow не запускался. Успешное сопряжение
на HP/S25 этим изменением ещё не подтверждено.

## Android 0.6.1: курсор-стрелка

Пользователь включил службу через найденное меню и подтвердил, что управление
работает. Затем сообщил, что курсор отображается точкой. В Pointer приложения
Galaxy Bridge Wi-Fi круг заменён белой стрелкой с чёрным контуром. Геометрия
создаётся один раз при появлении указателя, масштабируется по density экрана,
а начало пути совпадает с координатами нажатия. Координаты жестов и возврата
через край не менялись. Версия APK увеличена до 0.6.1 (601).

Проверены синтаксис Java tree-sitter, XML/структура исходников и неизменный
ручной workflow. Отображение новой стрелки на S25 не проверялось. Android SDK
здесь отсутствует: APK не собирался, workflow не запускался. Для применения
нужен новый ручной workflow и обновление Android-компонента. Из-за нового
тестового ключа workflow понадобится удалить старое приложение, установить
новое, снова включить службу и выполнить QR-сопряжение.

## Windows 0.6.2: скорость курсора и окно отправки

В LAN-режиме добавлена настройка существующего множителя InputCapture: 0,25–4
с шагом 0,05 и сбросом на 1. Изменение останавливает захват и сразу сохраняет
значение в Settings; при выходе из LAN-режима поле прежнего режима синхронизируется,
чтобы оно не записало старое значение поверх нового.

FileDropForm — отдельное окно с зоной перетаскивания, выбором нескольких файлов,
статусом соединения/передачи и отменой. Используется прежний SendAsync/SendFileAsync:
ограничения размера, проверка SHA-256, каталог MediaStore и обработка обрыва не менялись.
Новые файлы не принимаются при отключённом телефоне или занятой очереди.
Закрытие окна отправки оставляет передачу работающей; закрытие LAN-режима отменяет
её и закрывает окно. Неиспользуемая область QR скрывается, освобождая место для управления.

Проверка компилятором Roslyn 4.11 с reference assemblies .NET 8 и WinForms
прошла без ошибок и предупреждений; проверялись все исходники Core/Windows,
включая новый FileDropForm. Проверка структуры исходников также выполнена.
Запуск интерфейса на Windows, перетаскивание из Проводника, сохранение настроек
между запусками и отправка на S25 здесь не проверялись. EXE/APK не собирались,
workflow не запускался. Android-код и протокол не менялись.
