# Обновление Android без удаления приложения

Начиная с Galaxy Bridge Wi-Fi **0.7.4** и Galaxy Bridge Edge **0.3.2** ручной
workflow использует один постоянный ключ подписи. После перехода на эту подпись
откройте новый APK на телефоне и выберите **Обновить**. Сопряжение, настройки
и данные приложения сохраняются. Для работы новой версии может потребоваться
перезапуск приложения; повторный QR при обычном обновлении не нужен.

## Один раз настроить сборку

1. Откройте репозиторий `nashisvechi-spec/Galxybridge` → **Settings → Secrets
   and variables → Actions → New repository secret**.
2. Имя: **ANDROID_SIGNING_BUNDLE**.
3. В значение вставьте **всё содержимое** подготовленного файла
   `GalaxyBridge-AndroidSigningSecret.txt` и нажмите **Add secret**.
4. Запустите прежний ручной workflow **Build Windows portable**.

Файл содержит закрытый ключ и пароль. Сохраните его резервную копию для будущих
обновлений. Не загружайте его в исходники, релизы или общедоступные вложения.
В репозитории находится только открытый отпечаток сертификата:
`android/signing-cert.sha256`. Настройка GitHub Secrets недоступна через
использованный доступ к репозиторию, поэтому этот шаг выполняет владелец.

Первый шаг workflow проверяет ключ до сборки приложений. Если секрет отсутствует,
неверен или сертификат отличается от сохранённого отпечатка, сборка остановится.
Новый случайный ключ автоматически не создаётся. Подпись обоих APK постоянна;
имена пакетов остаются разными, приложения обновляются независимо.

## Переход с прежних тестовых APK

В прежних сборках закрытый ключ создавался во временной папке и удалялся
после сборки. Его нет в исходниках или в самом APK. Для перехода с этой подписи
нужно **один последний раз** удалить прежнее приложение и установить новый APK.
Удаление Galaxy Bridge Wi-Fi удалит сопряжение: снова включите специальные
возможности и выполните QR. Полученные файлы в общей папке Download/GalaxyBridge
при обычном удалении приложения остаются.

После перехода устанавливайте последующие APK поверх приложения.
Не удаляйте его перед обновлением и не меняйте сохранённый ключ.

## Номер сборки

В ручном workflow `versionCode` равен `100000 + GITHUB_RUN_NUMBER`: каждый
следующий запуск этого workflow получает больший номер для обоих APK.
Повторный запуск той же сборки сохраняет номер и подпись. Не пересоздавайте
workflow с обнулённой нумерацией без изменения схемы номеров версий.
Отображаемые версии Wi-Fi и Edge задаются в их скриптах сборки отдельно.

Для локальной сборки используйте PowerShell 7 и тот же сохранённый файл:

```powershell
$env:GALAXYBRIDGE_ANDROID_SIGNING_BUNDLE = Get-Content 'C:\private\GalaxyBridge-AndroidSigningSecret.txt' -Raw
./scripts/Test-AndroidSigning.ps1
./scripts/Build-LanCompanion.ps1 -Destination artifacts/GalaxyBridge -VersionCode 100500
./scripts/Build-EdgeHelper.ps1 -Destination artifacts/GalaxyBridge -VersionCode 100500
Remove-Item Env:GALAXYBRIDGE_ANDROID_SIGNING_BUNDLE
```

Задавайте `VersionCode` больше номера уже установленной сборки. Для APK,
установленного из workflow, локального номера 704/302 по умолчанию недостаточно:
это было бы понижение версии. Не используйте `-Verbose`, трассировку команд
или вывод переменных для файла подписи.

## Проверено

Скрипты подписи проверяются реальным keytool: восстановление одинакового
сертификата в двух независимых папках, отказ при отсутствующем/неверном секрете,
неверном пароле и несовпадении отпечатка. Тесты не создают APK или EXE.
Установка поверх старой версии и сохранение сопряжения требуют проверки на S25
после одноразового перехода на постоянную подпись.
