# Исследование Galaxy Bridge и подготовка 0.7.37

Все пять предложений ниже реализованы в 0.8.0:
[инструкция, ограничения и проверка](FEATURES_0.8.ru.md).
Остальной текст — исходное исследование 0.7.37.

Дата: 14 октября 2026 года. Основа — `main`, коммит `e40ac91`:
Windows 0.7.36 и Android 0.7.34. Изучены исходники WinForms и Android,
подключение, передача файлов, буфер, управление, сохранение настроек,
уведомления и установщик. Для новой версии обе платформы используют 0.7.37.

Это кандидат на релиз. Автоматическая проверка кода завершена; новую пару
Setup/APK и аппаратные сценарии нужно проверить перед стабильным выпуском.
Последняя прежняя сборка установщика прошла успешно:
[Actions, 13 октября](https://github.com/nashisvechi-spec/Galxybridge/actions/runs/38399830748).

## Что показало исследование

У приложения уже есть подходящая структура: четыре раздела Windows, три вкладки
Android, единый сине-бирюзовый стиль и независимый файловый виджет. Основные
затруднения связаны с объяснением состояния и доступностью действий. Полная
замена интерфейсной технологии сейчас добавила бы риск для работающей мыши
и передачи файлов; улучшения сделаны в существующих нативных приложениях.

Рекомендации платформ использованы как ориентир: понятные подписи, достаточно
крупные области нажатия, заголовки для экранного диктора, перенос длинного текста,
группировка настроек, немедленное применение и объяснение недоступных действий.
На Android обычные кнопки уже имели высоту не менее 52dp; устранено ограничение
в три строки, мешавшее крупному шрифту. Снимки настоящих Android views доступны
в [описании дизайна](UI_DESIGN.ru.md); это тестовая отрисовка, не снимки S25.

| Найденная проблема | Что изменено |
| --- | --- |
| На первом запуске неясно, что нужно для файлов, а что — для мыши | Пошаговое QR-подключение, отдельное объяснение разрешений и помощь с сетью |
| При потере связи пользователь может заново делать сопряжение | Пояснение восстановления сохранённого ПК без нового QR |
| Приём на ПК настраивался только в отдельном окне | Разрешение приёма, папка, изменение папки и отмена доступны в основной вкладке файлов |
| Недоступные действия выглядят непонятно; отмена активна без передачи | Кнопки учитывают состояние, рядом показывается причина; отмена доступна при передаче |
| Остановка и блокировка ПК отображались неоднозначно | Отдельные состояния в боковой панели и понятная кнопка возобновления |
| «Забыть телефон» сразу удаляло сопряжение Windows | Добавлено подтверждение с безопасным действием по умолчанию |
| Возврат QR-результата при открытой вкладке файлов мог обратиться к отсутствующему TextView | Обновление через проверяющий представления refresh, добавлен регрессионный тест |
| Возврат во вкладку Android сбрасывал прокрутку | Прокрутка сохраняется для каждой вкладки, в том числе при пересоздании окна |
| При выборе более 100 файлов отправлялась только часть | Вся подборка отклоняется с объяснением; отдельные тесты границ 100/101 |
| Повторяющиеся ClipData-элементы могли скрыть уникальный файл после сотой позиции | Лимит применяется к уникальным файлам |
| Старый VersionCode ручной сборки мешал обновлению установленного APK | Номер теперь обязателен; workflow продолжает увеличивать его автоматически |

Фоновая отправка через «Поделиться», имеющийся виджет и его прозрачность,
подпись Android, схема мыши и автоматический выбор DeX сохранены.

## Проверка

Пройдены 2527 проверок ядра и 82 Android-теста. Скомпилированы все исходники
Windows/Core и Android LAN. Просмотрены светлая/тёмная темы и файловая вкладка;
крупный текст проверен также при ширине 320dp. Подробности и границы проверки —
в [VALIDATION.md](VALIDATION.md), аппаратные сценарии — в [TESTING.md](TESTING.md).

Новый установщик и APK здесь не собраны. Обязательны обновление поверх прежней
версии, проверка настоящих файлов в обе стороны, звук уведомлений S25,
плавность курсора, блокировка/пробуждение, DeX и смена сети/VPN на устройствах.
Ни тестовая отрисовка, ни компиляция не заменяют эти проверки.

## Какие функции добавить дальше

Приоритеты ниже — вывод для этого приложения по результатам изучения кода и
сценариев. Это предложения, они не включены в 0.7.37.

| Приоритет | Функция | Польза и объём |
| --- | --- | --- |
| 1 | Докачка после обрыва связи | Большое видео не придётся отправлять с начала. Потребуются согласованное изменение протокола, временные файлы, смещения и итоговая проверка целостности. Сначала стоит поддержать переподключение в активном сеансе: доступ к URI после перезапуска зависит от источника файла. |
| 2 | Постоянная история и повтор передачи | Сейчас Windows хранит десять успешных файлов только до закрытия приложения. Нужны сохранённые успехи/ошибки, открыть файл/папку и повтор. Если доступ к исходному файлу утрачен, повтор должен предложить выбрать его заново. |
| 3 | Проверка подключения одной кнопкой | Показать доступность локальной сети, соединения, разрешений и возможную причину сбоя. Не менять VPN или брандмауэр автоматически. Это полезнее очередного общего сообщения «Нет связи». |
| 4 | Автозапуск Windows по желанию | Запуск в трей вместе с системой, понятная галочка и действие выхода. Проверить обновление/удаление установщика и сохранение пользовательского выбора. |
| 5 | Экран телефона в окне ПК | Просмотр и управление телефоном без перевода взгляда. Это отдельный этап: согласие на захват экрана, кодирование видео, задержка, поворот, DeX и нагрузка на телефон. |

Впоследствии можно добавить индикатор батареи и выбор нескольких доверенных
устройств. Сейчас выгоднее закончить устойчивую передачу и диагностику, прежде
чем расширять главный экран дополнительными панелями.

Для сравнения изучены официальные описания Quick Share, KDE Connect и Phone Link:
у Quick Share акцент на передаче между устройствами, у KDE Connect — на файлах,
буфере и удалённых действиях, у Phone Link есть сценарий экрана телефона для
поддерживаемых устройств. Это ориентиры сценариев; использовать их закрытые
драйверы или предполагать одинаковую совместимость не требуется.
